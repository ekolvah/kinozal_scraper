## Why

Epic #616 (step 3) split the #612 audit into four PRs; this is **D** (#628), the last, and it closes
#612. A (#629/#630), B (#637) and C (#638) are merged.

Observations (main @ `4f966e2`, plugin 3.10.1):

- **Ruff is declared twice, in bespoke code.** `scripts/ci_check.py` `check_format`/`check_lint`
  run `python -m ruff format --check .` / `ruff check .`; `scripts/hooks.py on-edit` runs the same
  two commands per edited `*.py` from a `PostToolUse` entry in `.claude/settings.json`. Both take
  ruff from `requirements-dev.txt` (`ruff==0.15.12`).
- **The plugin already ships the edit-time trigger.** Upstream ADR 0034 (installed 3.10.1,
  `.agent-process/docs/adr/0034-…`): "The plugin's `PostToolUse` `Edit|Write` hook runs
  `agent-process edit_lint post-edit`: `pre-commit run --hook-stage pre-commit --files <edited
  path>`". This repository's `.pre-commit-config.yaml` has no `pre-commit`-stage hook, so that
  trigger runs nothing here today. The plugin's own repository made the same move: "`ci_check`
  `lint` runs `pre-commit run --hook-stage pre-commit --all-files --show-diff-on-failure`;
  `format` is no longer a check. `hooks.py` and its settings entry are deleted."
- **An upgrade keeps hooks of our own.** Installed `openspec/specs/distribution/spec.md`: "An
  existing `.pre-commit-config.yaml` SHALL keep every byte outside the block", scenario "Existing
  config keeps its hooks". The plugin's `quality` hook is `stages: [pre-push]`
  (`.pre-commit-hooks.yaml`), so `--hook-stage pre-commit` does not nest it.
- **A rewriting formatter does not break the next `Edit`.** Live in this session: a file was
  rewritten by `ruff format` behind the harness; the harness reported the new content ("changed
  on disk since you last read it") and the next `Edit` against that content succeeded without a
  re-`Read`. The premise of `hooks.py` ("rewriting behind its back breaks the next Edit") no longer
  holds.
- **The `pip-compile` hook condition of #628 is met literally but fails in practice.** The
  lockfiles are real `pip-compile` output with transitive pins (`requirements.txt` header
  "autogenerated by pip-compile with Python 3.12", `# via` lines). But they are compiled on
  Windows: `requirements-dev.txt` pins `colorama==0.4.6` "via build, click", a Windows-only
  dependency of both. pip-tools README: "As the resulting `requirements.txt` can differ for each
  environment, users must execute `pip-compile` on each Python environment separately". A
  `pre-commit`-stage hook also runs in `ci_check lint --all-files` on Linux CI, where it would
  rewrite `requirements-dev.txt` and turn every run red.
- **`agent-process.md` is gone (#638)**, so the list of what stays (#612 acceptance 3) goes to
  `project-map.md`.

## What Changes

- **Ruff moves into `.pre-commit-config.yaml`** as `ruff-check` and `ruff-format` of
  `astral-sh/ruff-pre-commit` at `rev: v0.15.12`, `stages: [pre-commit]`, outside the
  agent-process block. The `rev` becomes ruff's only pin; `ruff` leaves `requirements-dev.in`/`.txt`.
- **`ci_check.py`**: `check_lint` runs `python -m pre_commit run --hook-stage pre-commit
  --all-files --show-diff-on-failure`; `check_format` and the `format` registry entry go.
- **`tests/test_ruff_first_party_imports.py`** runs the real ruff through the hook pinned in
  `.pre-commit-config.yaml` instead of `python -m ruff` (design D3).
- **Delete** `scripts/hooks.py`, `tests/test_hooks.py` and the `PostToolUse` block of
  `.claude/settings.json`. The `requirements*.in` reminder is not replaced; `check_requirements`
  stays the catcher (design D4).
- **`project-map.md`** gains the list of repository-owned process files that stay, each with its
  reason or owning issue.
- Docs follow: the `pre-commit` decision in `ci-tooling-decisions.md`, the gate order and the
  session-hook section of `ci-local.md`, `ci-workflow.md`, ledger entry `X` and new entry `AT`.
